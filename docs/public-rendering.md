# 公开页面服务端渲染（0.0.1-beta.4）

## 本轮完成了什么

首页、指标目录、指标正文、器官正文由现有 Next.js 服务输出 HTML，复用根目录 `src/` 的 React 组件与样式。正文、参考来源、版本、待审校提示和真实导航链接在禁用 JavaScript 时仍可阅读；浏览器加载后接管搜索、筛选、收藏、人体交互、分享和纠错。

每个知识页具备独立标题、描述、canonical、Open Graph 与 Twitter 摘要信息。元信息和页面使用同一次请求的已发布快照，不读取编辑草稿，不额外在首次浏览器挂载时重取正文。未知内容、未知页面、已撤回内容返回真正的 404；撤回页不回显旧标题或正文。服务失败显示错误，不回退到打包的旧 JSON。

本轮采用**动态 SSR，而非 SSG / ISR**。当前内容规模小，医学内容撤回一致性比缓存收益更重要，因此每次请求读取发布集合，HTML 和内容 API 均不缓存。站点不把错误页面包装成 200。以后引入持久页面缓存时，必须先实现发布事件、即时撤回失效、失败重试与版本一致性测试，不能直接加固定过期时间。

## 同一套前端，两个运行入口

- `src/App.jsx`、组件与样式：唯一的读者页面实现。
- `src/main.jsx`：Vite 离线/开发入口，继续支持无需后端的本地演示。
- `backend/scripts/sync-reader.mjs`：构建前把读者源代码复制到忽略提交的 `backend/reader/`，复制 favicon 到后台 public 目录。不要直接编辑生成目录；新一次构建从根目录源代码生成。
- `backend/src/site.ts`：根据公开路由查询已发布快照，生成首屏数据和元信息。React request cache 只在一次服务端渲染请求中去重，不是跨请求文章缓存。
- `backend/src/app/(site)/`：公开路由和布局；`(payload)` 仍负责后台与 API。

Next.js 的构建上下文现在是整个仓库：使用根目录 Compose，或 `docker build -f backend/Dockerfile .`，不再单独从 backend 目录构建镜像。生产镜像仅包含需要的源代码、依赖和构建产物，不打包私有环境、备份或本地数据库。

导航、知识卡片、器官标签、相关内容和来源引用是原生链接，支持不开脚本、复制链接和新标签页打开。线上跨页面采用完整文档导航，避免客户端长时间复用旧正文或旧元信息；Vite 演示保留 History 的轻量单页导航。浏览器从页面恢复缓存返回时重新请求当前内容。

本地收藏继续使用 `zhiyu-saved`，没有换键或上传用户收藏。服务端只输出收藏页框架；挂载后恢复浏览器数据，恢复之前不会用空数组覆盖已有收藏。

## 索引与医学内容边界

运行时 `SITE_CONTENT_CHANNEL` 只允许 `official` 或 `demo`，默认为正式集合。选择演示集合还必须显式启用 `ENABLE_DEMO_API=true`。

演示集合所有公开 HTML 带 `noindex`，sitemap 为空；不会把未审校内容当作正式医学知识主动推送给搜索引擎。正式集合仅使用正式发布记录，sitemap 只包含当前未撤回的公开内容及首页/目录，不包含演示、草稿、收藏和后台。收藏页始终 noindex。

`robots.txt` 限制后台、API 与收藏路径的抓取；这是爬虫建议，不代替鉴权。元信息不意味着搜索引擎已收录，也不保证排名。Open Graph 不自动实现微信 JS-SDK 自定义分享卡片；当前不生成专题缩略图、不声称已通过各平台真实分享验收。

本轮没有增加医学结论、生成医生身份或创建真实医学审校。待审校状态、引用与版本信息来自原有发布快照。

## 升级部署

1. 备份数据库、旧站点配置和镜像；保留回退所需的旧静态资源。
2. 在私有环境文件设置 `SITE_CONTENT_CHANNEL=demo` 或 `official`。演示还需开启 `ENABLE_DEMO_API`；`SERVER_URL` 必须是实际公开来源，避免 canonical 和同源纠错校验错误。
3. 从仓库根目录构建并启动 CMS 服务。该服务现在同时承载读者页面；本版未增加数据库表或迁移，不需重新导入内容。
4. 按 [全站代理示例](../deploy/nginx-ssr.conf.example) 将公开页面、后台与 API 一起代理到 Next.js，停止对知识页面回退 `dist/index.html`。保留 HTTPS 与真实客户端地址覆盖配置，不在代理/CDN 缓存 HTML/API/sitemap。
5. 停止公开旧 `/content/` JSON，避免绕过发布与撤回。旧 `/assets/` 可在迁移窗口保留，供已打开的旧标签页读取 JS/CSS；新网站使用 `/_next/` 资源。
6. 检查 HTML 正文、元信息、状态码、移动交互、已有收藏和纠错。若需回退，仅恢复此前镜像/路由与静态资源，不覆盖或回滚生产数据库。

根目录 `npm run build` 仍生成 Vite 静态演示，不是生产 SSR 站点发布步骤。仅需要离线演示时可以继续使用原 [静态 Nginx 示例](../deploy/nginx.conf.example)。

## 验证与已知限制

- `scripts/ssr-smoke.mjs`：无脚本正文与导航、canonical/robots、真实 404、不重复拉取首屏正文、收藏恢复、搜索、分享、旧 Hash 链接与移动端布局。
- `backend/scripts/rendering.test.ts`：只允许独立 `zhiyu_test` 数据库，测试草稿隔离、发布、版本切换、回滚、撤回、正式/演示隔离。设置本地 `RENDER_TEST_BASE_URL` 后同时验证真实 HTTP HTML 和状态码；不能指向线上进行变更测试。
- 原有静态模式浏览器测试继续覆盖分页、失败重试与基本交互；纠错与审校流程测试继续保留。

数据库不可用会影响公开页面读取。本轮选择正确报错，不提供可能已被撤回的陈旧副本；高可用、自动备份与容量测试仍需独立建设。无缓存 SSR 的成本需要真实访问量来测量，目前不承诺吞吐量或核心网页指标达标。

首屏只加载当前页面所需数据，搜索和翻页仍通过 API；目录未新增可抓取分页 URL。sitemap 暂为单文件，上限为 50,000 个 URL，规模接近上限时需拆分 sitemap 索引。真实手机、微信内置浏览器和第三方分享抓取仍须单独验收。
