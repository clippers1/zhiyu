# 知愈：从体检疑问出发的健康知识产品方案（讨论稿）

日期：2026-09-23。状态：**H02（首页第一刀）、H03（列表与搜索）与 H04 工程侧（详情可选图解模板）已实施；H04 内容核对、H05–H06 待人工/后续**；不是医学内容发布许可。本方案提出对 [现有产品规划](product-plan.md) 的调整，旧规划暂保留为历史基线，确认后再同步正式路线图。用户需求假设、专业复核者与目标地域仍待验证。

## 1. 摘要

知愈先帮助普通人把**体检单上的常见项目与日常健康疑问**讲明白，再串起相关慢性病基础知识和器官原理。首页不再要求用户先选器官或理解“知识地图”；用“我刚看到什么 / 我想弄懂什么”的问题找到一篇能解决疑问的内容。脑科学和婴幼儿心理与发展是以后可验证的独立栏目，不同时抢占首页和编辑资源。

一句话定位：**看懂一个健康问题，再知道哪些事不能仅凭一项结果判断。**

不做：上传个人报告后自动诊断、按数值判断疾病或提供治疗方案、儿童发育打分、以“权威背书”替代逐条来源核对。

## 2. 负责人和待确认事项

| 角色 | 责任 | 当前状态 |
| --- | --- | --- |
| 产品/内容负责人 | 确定首批问题、范围、中文表达与更新机制 | 待指定 |

待确认：读者主要来自中国大陆还是更广的中文地区？当前有没有可长期合作的相应专业复核者？这两个答案决定疾病/数值/婴幼儿板块何时能够公开，不阻碍第一阶段基础知识整理。

## 3. 背景与现状

- 站点已有 9 个指标专题、5 个器官专题及搜索、来源、CMS、撤回、分享等能力；现有导航为“健康地图 / 指标百科 / 器官探索”。这些是基础，不应因重定位而重建。
- 当前产品规划以“器官如何运作”为第一切入点；当前内容扩展流程明确排除疾病判断、数值阈值和个体诊疗。**本提案的疾病、儿童内容因此是新风险等级，不得直接套用既有的基础知识快速发布流程。**
- 缺的不是更多功能按钮，而是面向真实问题的内容组织：搜索得到项目名称，但读者的问题常是“这一项是什么意思”“和另一项有什么区别”“该向医生问什么”。这个判断目前是产品假设，不是已证实的用户研究结论。
- 慢性病选题聚焦血压、血糖、血脂有公共卫生依据，但不等于站点已经具备向个人提供诊疗意见的资质；检验参考范围可能因实验室和人群不同而异，不能做统一的“正常值裁判”。

## 4. 目标与验证

**北极星任务：**用户从自己的问题出发，找到可核对的解释，读完能说出“这项是什么、不能说明什么、下一步如何获取专业帮助”。

第一轮验证（目标，不是现有业绩）：

1. 找 5–8 位目标读者，覆盖能读体检单的工作年龄读者与有家中长辈体检需求的读者；观察各自找 2 个具体问题的过程。记录入口、搜索词、误解、退出点，不采集报告或数值。
2. 任务完成判据：读者不经提示能找到对应内容，并能复述至少一个“不能据此下结论”的边界；如出现危险误解，先修文案和信息架构，不放量。
3. 技术基础：移动端可直接访问、搜索结果与正式可读内容一致、来源可打开、撤回后不可继续从站内进入；复用既有发布/回滚测试。
4. 建立基线后再定量化目标：优先记录匿名汇总的查找成功/失败、问题卡进入详情率、自愿提交的“没找到/没看懂”反馈和内容维护耗时；不把文章数、停留时长当作理解质量。不默认持久化包含健康信息的原始搜索词，必要的选题收集先设计匿名化、告知和删除方式。

## 5. 用户、任务和范围

按**当下想解决的问题**划分，而不是把“老人、打工仔、家长”作为互斥的三套产品：

| 用户情境 | 想完成的事 | 首期满足方式 | 暂不满足 |
| --- | --- | --- | --- |
| 拿到自己或父母的体检单 | 快速弄懂常见项目的含义和局限 | 项目解释、术语卡、相关问题导航 | 上传报告、解读个人数值 |
| 关注慢病的家庭 | 理解血压/血糖/血脂与长期健康的基本关系 | 入门问题、非个体化疾病概念，**通过额外复核后**发布 | 病情分级、用药和监测方案 |
| 对原理感兴趣的读者 | 理解身体或脑的一项机制 | 现有心肺互动；脑科学候选主题待验证 | 用“神经科学”包装缺少证据的建议 |
| 关注婴幼儿发展的家长 | 理解亲子互动和发展观察的基本概念 | 后续独立试点，先做无诊断含义的基础知识 | 仅凭年龄/清单给发育结论 |

**首期唯一主线：体检疑问 → 常见指标 → 必要的慢病常识 → 认识机制。** 年龄不是导航分类；首页不同时陈列四个内容宇宙。老人友好通过字号、措辞、点击区域与阅读顺序解决，而不是建立“老年专区”。

## 6. 内容价值与生产规则

一张内容卡只回答**一个明确问题**；多张卡可以复用同一篇已核对的长文和来源，不靠生成大量同义短文“补数据”。

| 层级 | 内容例子（标题为问题，不是医学结论） | 内容类型 | 发布门槛 |
| --- | --- | --- | --- |
| A 已有基础 | “血糖项目主要看什么？”“血脂单里几个名称有什么区别？”“尿酸是什么？” | 改写现有 9 个指标的标题、摘要、别名与入口；新增问题入口 | 沿用现有来源逐点核对，显示现有核对状态 |
| B 基础扩展 | “肌酐和肾功能是什么关系？”“血常规里常见名称各指什么？”“空腹和餐后项目有什么区别？” | 现有知识的子问题/词条，缺处补可靠来源 | 清晰区分项目定义与个人结果解读；内容与目录同步发布 |
| C 慢病基础 | “高血压与一次血压升高是同一回事吗？”“糖尿病和血糖偏高是同一回事吗？” | 新疾病类内容，按中国大陆受众核对本地适用性 | 专业复核、适用人群、更新日期、就医边界；不复用 A/B 快速发布通道 |
| D 兴趣支线 | “睡眠和记忆的关系怎么研究？”“宝宝通过互动学习什么？” | 小规模脑科学 / 婴幼儿发展试点 | 先验证需求及有无对应来源和审阅能力；儿童内容另做专业复核 |

首轮具体工作包：**整理现有血压、血糖、血脂三篇为问题式入口**，补齐读者常用别名和“不能说明什么”；另从其余 6 个指标中挑 2 篇按实际未命中词处理。新增慢病篇先写脚本和审阅样稿，不因追求内容量而直接上线。以上数量是小批验证工作量，不是内容目标。

每个知识单元记录：用户原话/搜索别名、回答一句话、必要解释、不能据此判断什么、适用人群、来源对应位置、来源核对日期、内容责任人、内容版本、专业复核（若需要）、关联问题。**不使用生成式模型自动拼装医学结论**；无确切来源、未核对或已撤回时不出现在推荐/搜索中。现有来源与发布流水线可以作为基础，但疾病与儿童发布门槛需要单独设计和测试。

资料起点（不能取代逐篇核对和本地化核对）：[WHO 非传染性疾病概况](https://www.who.int/news-room/fact-sheets/detail/noncommunicable-diseases)、[MedlinePlus 怎样理解化验结果](https://medlineplus.gov/lab-tests/how-to-understand-your-lab-results/)、[CDC 儿童发育观察与筛查的区别](https://www.cdc.gov/act-early/about/developmental-monitoring-and-screening.html)。

### 6.1 图文优先的生产方式与成本控制

**不是每篇都做一段动画。**先确定读者要理解的关系，再选最省工、能准确表达的载体：

| 层级 | 适用问题 | 交付形式 | 主要成本 |
| --- | --- | --- | --- |
| 1：图解卡 | 术语、项目对照、组成关系 | 一张主图 + 标签 + 贴图短文字 + 完整文字版 | 核对知识点、术语与图示简化 |
| 2：分步图 | 有先后、因果或流向的问题 | 复用同一张底图的 3–5 个高亮状态，可手动切换 | 脚本、步骤准确性与手机阅读测试 |
| 3：轻动画 | 静态图确实无法讲清的过程 | 在已核对分步图上加可暂停的移动/渐变，保留静态版 | 动效实现、无障碍、误读风险与维护 |

首批三个样板（血糖、血压、血脂）先尝试层级 1，不预设哪个必须做动画；只有读者测试表明“分步仍看不懂”，才把相应主题升到层级 3。心脏、肺部已具备互动样板和授权插图，可复用展示和步骤控制模式，**但不把器官素材当成新疾病图示的医学依据**。

每篇的固定产物是：问题与答案脚本 → 对应来源/图示依据 → 视觉草图 → 中文标签 → 静态无动画版 → 来源与许可记录。可复用底图、标签样式、箭头/高亮/步骤组件；不得直接复制搜索到的“医学图”或套用来源不明的 AI 生成人体图。项目已使用 Servier Medical Art 的 CC BY 4.0 器官插图；使用或改动时保留署名、许可链接及修改说明，具体文件归属见 [医学插图来源与授权](media-attribution.md)。其他图片须逐张核对授权，不假设整站内容都可复用。

**成本估算方法：**第一批逐项记录“资料查证 / 脚本 / 绘图 / 动效 / 复核 / 修改”的实际工时；做到第二批再比较模板复用节省了多少。当前没有实测工时，不承诺“每周产出几篇”或预报单篇费用。若图示方向、适用人群、授权或医学表达有疑问，先改静态图和文字，不把错误做得更精致。

### 6.2 非医学专业维护者的视觉制作流程

**角色边界：**维护者负责选题、查找和整理来源、将已经核对的知识翻译成图文、组织读者测试；不能凭直觉创造医学事实，也不能自行确认有争议的疾病判断正确。易懂和科学准确是两道不同的验收关：读者能复述，不代表图中箭头、比例和因果关系正确。

每个图解/分镜保留一张可审阅的“视觉脚本卡”，至少写明：

| 字段 | 要记录什么 |
| --- | --- |
| 唯一问题 | 读者看完后应能回答的一个问题；不同时解释多种机制 |
| 核心说法与依据 | 每一幅/每一步的一句话结论、对应的来源章节或图号；找不到直接依据就删去说法 |
| 视觉元素 | 标签、箭头、颜色、相对大小、先后顺序分别表示什么；标明示意而非真实比例或速度的地方 |
| 适用与省略 | 哪些人群/场景适用，省略了什么；会造成错误理解的省略不得靠免责声明补救 |
| 素材与权利 | 底图作者、原链接、许可、是否改编、页面/视频/分享卡各自的署名位置 |
| 验收记录 | 来源核对人与日期、读者复述结果、待澄清疑点、复核结论及发布版本 |

制作顺序：

1. **从已有知识出发。**优先挑已在站内核对过的基础解释，核对具体段落是否真的支持将要画出的关系；来源能证明事实，不等于来源中的图片也可转载。
2. **先写短句和静态图。**每幅图只讲一个关系，先把 3–5 幅分镜按顺序排好。可以复用已授权的器官底图、项目卡样式、标注/箭头/高亮组件；不要逐篇重画全套人体结构。
3. **逐元素检查“暗示”。**箭头方向、粗细、位置、颜色、比例、出现先后、循环次数和动画速度都可能被当作真实生理关系；示意简化写进图注，必要时用文字标签代替不可靠的精细绘制。不用统一的“正常值”刻度或红绿灯代表个人诊断。
4. **静态仍不清楚再加动画。**优先复用分镜的状态切换和高亮，能手动前后切换、暂停、减少动态效果，并有完整静态文字版；不靠自动播放、循环特效制造“科学感”。
5. **分开做两次审查。**普通读者不看解释先说“这幅图在说什么”，发现误读就改设计；随后对照来源逐项检查图和文字的科学表达、边界与许可。读者测试不能取代内容核对；对于疾病、数值、药物、特殊人群和婴幼儿发展，再进入相应专业人员复核，未完成不得公开。
6. **发布与维护。**把图示与正文作为同一内容版本发布，标明示意边界、来源、日期与纠错入口；来源更新或解释有疑点时能撤回/修订，分享卡与导出视频同样核对署名与图示版本。

**AI 的使用边界：**可以协助列分镜备选、排版、配色和生成非医学装饰草图；人体结构、项目关系、标签、箭头及医学结论必须由可定位的来源和人工核对决定。AI 生成的“看起来专业”的人体图、数值图或婴幼儿发育图不得直接发布；没有使用权证明的参考图也不能靠 AI 重画来规避授权。

**停工条件：**来源不能直接支持某幅画面、不同来源存在冲突、图片权利不明、读者将示意图误认成个人诊断，或高风险内容找不到相应专业复核者时，该幅图保持草稿，必要时退回纯文字基础解释。若普通知识也无法确认图示准确，宁可不画，不为完成视觉配额上线。

参考规范：[CDC Clear Communication Index](https://www.cdc.gov/ccindex/tool/how-to-use.html) 可用于检查图文是否清晰，但不取代来源与专业核对；[Servier Medical Art 使用及署名说明](https://smart.servier.com/using-smart-images-what-you-can-do/) 与 [CC BY 4.0 条款](https://creativecommons.org/licenses/by/4.0/) 用于核对其图像的再利用、改编和署名要求。Servier 网站的其他页面元素不因插图使用许可而自动获准转载。

## 7. 页面和用户流程

### 7.1 信息架构（建议，不代表现有路由）


### 7.4 搜索与疾病/儿童页差异

- 搜索结果按“问题 → 项目/术语 → 器官原理”分组；标识对应内容类型。未命中时提供同义词建议和“没找到我想问的”，**不伪造答案、不把器官内容冒充疾病建议**。
- 慢病页需独立模板：普通话概述、常见误区、与检查项目的关系、哪些情况应寻求专业帮助、来源及适用版本；没有复核者先不发布。
- 儿童页若获准试点，用“观察与互动”而非“正常/不正常”的年龄打分；观察清单不替代标准化发育筛查，担忧时建议与儿童保健/儿科专业人员讨论。

### 7.5 页面可用性验收

低视力/高龄读者可调字号且无文字截断；主要按钮和问题卡易点；不用纯颜色表达异常；不自动播放动画；图文完整可读；来源可追溯；屏幕阅读器能按标题找到“回答 / 局限 / 来源”。测试微信内置浏览器和常见手机宽度，保持旧分享链接可用；自动化截图也要先确认中文字体成功加载，不能拿缺字方框评价最终排版。

### 7.7 视觉与交互细节（首期）

- **层级：**手机按“问题 → 能否立即回答 → 图示 → 限制 → 详解 → 来源”单列阅读；桌面将问题和有意义的示意并列，但不能把主要答案藏到装饰插画后。首屏不以器官图或装饰性大幅英雄图区抢占搜索与问题入口。
- **卡片：**问题为卡片主标题；配图必须与这一问题有直接关系，并有替代文本。没有已核对图像时使用文本卡，不拿泛用器官插图暗示医学结论。卡片辅助行区分“体检项目 / 人体原理”，不显示未经统计的“热门”。
- **图解：**同一知识点可展示“总览图 → 标签 → 3–5 步”；每步有短句、高亮与对应来源。默认静止，手机手动切换，切图后屏幕阅读器能获知当前步骤；尊重减少动态效果偏好。图中的颜色不是唯一含义，箭头与文字也要说清关系。
- **文案：**按钮用“搜索健康术语”“阅读血脂解读”等明确动作，不用“开启探索”代替任务说明；问题标题只承诺正文真正回答的内容。科普限制靠具体解释和来源支撑，不靠固定免责声明单独放行。
- **适配：**保持既有字号偏好和移动端导航；320–430px 下搜索按钮、问题卡不横向溢出；桌面宽屏可双列但维持自然阅读顺序；图像使用容器约束而不裁掉医学标签。

### 7.8 内容字段、状态和系统依赖

**首期不新增疾病类型或平行 CMS。**现有 `indicator`、`organ`、来源库、发布版本与撤回规则保持原样。问题入口是已发布专题的编辑呈现，不能把标题当成另一份未经审核的医学正文。

| 字段/约束 | 首期实现 | 后续扩展门槛 |
| --- | --- | --- |
| `id`、`kind`、`title`、`subtitle`、搜索别名 | 继续由现有内容列表和详情提供；首页问题卡在已返回的可读项上加任务式文案 | 编辑配置问题与内容 ID 的显式映射；同版本发布/撤回，禁止悬空链接 |

### 7.10 逐页验收场景与状态约定

| 场景 | 预期行为（通过条件） |
| --- | --- |
| 体检单上看到“血脂” | 首页搜索或问题卡能进入正式可读的血脂文章；标题所问能从正文找到答案；能找到“不能说明什么”和来源 |
