# 知愈产品蓝图：内容型健康知识产品，而非空社区

更新：2026-09-26 · **当前产品与解决方案的实施依据（建议稿）**。适用前提：个人或小团队、尚无用户研究/稳定创作者和医生团队、先以现有移动网页交付。不把访谈、外部平台运营或市场验证设为开工前置条件；也不把基于案头研究的判断冒充已获得市场认可。旧演示版和已有正式/演示内容均不因本文自动变更。配色与品牌视觉另议。

## 1. 产品决策：今天就能做什么判断

**建议做成「好逛、好找、好分享的健康图文知识站」：用成熟内容 App 的浏览方式承载编辑精选的作品，以搜索和专题承接有明确问题的人。**首期是一个能像内容产品一样阅读的移动网站，不是论坛、问诊入口、AI 诊断器，也不是必须从第一课学起的课程。可在现有社区发布节选获客，但**经营外部账号不是开发或上线的必要条件**。

一句话用户承诺：**刷到一个和自己或家人有关的问题，几分钟内看懂一个意思；有具体词要查时能直接找到解释，想转给家人时不必让对方下载 App。**这是产品目标而非已验证的用户陈述；无资质不暗示个人诊疗或“医生都推荐”。

**不承诺「大众都喜欢」。**大众接受度不是布局或某项功能能保证的；在无调查条件下，专业决策应优先选择已经被广泛采用的交互模式、范围清晰的内容、可以独立交付的版本和低代价可逆的选择。做完后才有真实表现可供判断，不能用竞品规模推算知愈的用户规模。

## 2. 市场参照：观察、推断和取舍

截至 2026-09-26，核对中国区 App Store 开发者介绍和当前版本时间：[小红书](https://apps.apple.com/cn/app/id741292507)、[抖音](https://apps.apple.com/cn/app/id1142110895)、[知乎](https://apps.apple.com/cn/app/id432274380)、[豆瓣](https://apps.apple.com/cn/app/id907002334)、[丁香医生](https://apps.apple.com/cn/app/id911261462)、[蚂蚁阿福](https://apps.apple.com/cn/app/id6743828427)。这些是**开发者陈述/展示，不能证明某个页面的转化率或当前市场份额**。QuestMobile [2026 年 4 月 APP 流量竞争报告](https://www.questmobile.com.cn/research/report/2043979270875897857/) 的标题称「半数行业前三玩家切走八成流量」：这是其报告所研究行业的集中现象，不是健康内容细分赛道份额，更不是对知愈获客能力的测量。以下「为什么」是产品推断，不是已发表的因果研究。

| 已有产品呈现的模式 | 用户熟悉的动作 | 知愈的对应设计 | 不能照搬的依赖 |
| --- | --- | --- | --- |
| 小红书：兴趣发现、内容创作与互动 | 看封面、点图文、滑读、收藏、分享 | 有封面的有限内容流、直达图文、相关推荐 | 海量作者、关注关系、双列无限刷、虚构评论与热度 |
| 抖音：视频、直播与长辈模式 | 立刻看内容、顺手连续观看 | 快速进入主题、易点的大字控件；真有视频再提供主动播放 | 高视频生产量、自动播放、靠算法填满内容 |
| 知乎：问题与回答；豆瓣：主题、条目与小组 | 围绕问题查找、沿话题深挖 | 读者原话式标题、真实专题、相关作品 | 空问答、假小组、未管理的用户医疗建议 |
| 丁香医生：科普、百科与问诊；蚂蚁阿福：AI 和健康工具 | 有具体健康问题时搜索、获取服务 | 把搜索与内容浏览分开，已有指标作为查找型内容 | 医生资质、医疗服务、上传报告后的个体化结论 |

**反直觉但重要的选择：**复制社区的排版相对容易，复制「内容库存、创作者、讨论治理和分发」不容易。现阶段可以做成**有内容产品体验的编辑站**，不能仅因为信息流长得像社区就称自己有社区。也不假设必须具备别人没有的功能才能启动：首期价值来自问题选得准、图解释得清、旧内容找得回；这些是待兑现的能力，不是排他的护城河。

在现有资源约束下，对四种产品形态的定性取舍如下（**产品经理判断，不是市场调研打分**）：

| 形态 | 读者能立即得到什么 | 主要资源/风险 | 决策 |
| --- | --- | --- | --- |
| 纯指标查询工具 | 有目标地找术语 | 已有存量可复用，但随手打开和连续阅读理由弱 | **保留为第二条主路径**，不让它定义整个品牌 |
| 编辑型图文发现 + 查找 | 看一篇有趣解释，也能查具体问题 | 要持续做真实作品、处理授权和医学边界 | **首期主形态**；只承诺有限、精挑的内容，不装作日更 |
| 开放健康论坛/问答 | 用户彼此讨论 | 需要贡献者、治理和医疗误导/隐私处理；冷启动空场 | 不立项；编辑收集匿名选题可替代部分需求 |
| 视频/AI 健康助手 | 沉浸观看或即时个性化回应 | 视频制作与审核成本，个体化医疗风险和竞品能力差距 | 不做主形态；有合适素材再做可控短动画 |

## 3. 受众与使用时刻：不用一上来讨好所有人

首期服务的是**有生活健康好奇心、偶尔要给家人解释问题的中文普通读者**，按使用任务而非武断按年龄分组。下表是设计假设，不是调研发现。

| 使用时刻 | 用户想完成的事 | 推荐入口与产物 | 首期边界 |
| --- | --- | --- | --- |
| 碎片时间随手看看 | 有意思、与自己相关、看完还想读一篇 | 发现页封面图文 → 短段滑读 → 同主题下一篇 | 无真实作品就停止列表，不造无限流 |
| 家人发来一个词/体检名称 | 直接弄清「这个词在说什么」 | 顶部搜索 → 现有指标/基础解释 → 可分享直达链接 | 不收报告/检测值，不判断个人结果 |
| 想给长辈转一篇 | 对方点开就读，文字和图都清楚 | 微信等渠道的可读深链、清晰标题、大字阅读 | 不强迫注册、进 App 或完成学习任务 |
| 想看脑科学/婴幼儿成长/慢病 | 希望解释可靠、不吓人 | 暂列为后续栏目候选 | 无相应来源与复核资源不开放空频道，更不做儿童打分 |

首期主叙事围绕**身体与日常**；「体检项目」留作搜索入口而非全站定位。「脑与行为」「陪孩子成长」「慢病基础」是三个不同的编辑专业领域，不是换标签就能上线的栏目。直面老人、家长、打工人的所有需求同时开张，会造成内容太稀、写作边界混乱和不可信的导航。

## 4. 产品结构：读者看到的具体形态

**两条平行主路径**：① 没有具体问题 → 发现 → 打开图文 → 接着读/分享；② 带着问题来 → 搜索/目录 → 找到已有解释 → 关闭或分享。两条都不需要答题、核对打分、路径进度或用户画像。

```text
发现（首页） ──→ 图文详情 ──→ 真实相关作品 / 分享
    │                 │
    └── 搜索/专题 ←───┘
          ├── 现有体检项目与基础文章
          └── 认识身体（现有器官互动，按需深读）
```

首期沿用现有 `/`、`/article/:id`、`/indicators`、器官和专题链接；不为新名称破坏收藏/外链。频道只有真实作品支持时才露出。**不先上多栏底部导航**：首屏明确「发现」「搜索」，内容足够后再提供「专题」入口；是否需要固定底栏由实际信息层级而不是主流 App 的外观决定。

| 页面 | 首屏顺序与排版 | 交互、状态与边界 |
| --- | --- | --- |
| 发现 `/` | 简短站名/搜索 → 一张完整主封面+问题标题+引子 → 不重复的后续图文卡 → 有真实内容才展示专题/指标出口 | 手机**先用单列大卡**，保证标题和图可读；桌面可有限双列但正文仍单列。无人工内容时露出现有目录，不放占位帖、假「热门」；不默认无限加载 |
| 图文详情 | 栏目/标题 → 立刻进入具体情境与第一幅有用的图或解释 → 图、短段、局部小标题自然交错 → 相关一篇 → 来源/更新/纠错 | 图集左右切换可用，但不强制翻页；封面、正文与限定条件同版本；坏图保留文字，动画手动控制并有静态等价内容；不伪造作者或医生身份 |
| 搜索/目录 | 输入优先，结果显示真实题目、类别和一句忠于原文的描述；搜索结果与「发现」排序分开 | 同义词/缩写可找，空结果诚实说明无内容；加载/撤回/失败不显示旧医学快照；问题征集不收个人病史 |
| 专题/认识身体 | 真正相连的几篇文章构成主题，器官互动是**深入阅读**入口 | 少于足够形成系列的作品时不造空专题；旧路线可访问但不作为浏览前置任务 |

**版式默认值不是审美定稿**：手机先单列阅读，封面可辨识但不为统一比例裁掉医学关键信息；标题用读者语言、正文尽早给有用解释；明确信息层级和留白，绝不靠绿色大面积铺底来制造医疗感。支持 320–430px、放大文字、键盘/屏幕阅读器、减少动态效果、低网速与微信内浏览器；字号放大时结构不断裂。无 JS 和分享直达页面应可读。可用性依据参考 [WCAG 2.2](https://www.w3.org/TR/WCAG22/)；配色待后续确定。

## 5. 内容是产品库存，不是页面填料

**上线内容建议：**从现有 9 个指标与 5 个器官条目中梳理可公开、可回查的基础解释，作为搜索和关联阅读的存量；另制作**4–6 篇真正不同的图文作品**支撑发现页。这是「有限列表不要重复/空」的工作量估算，不是已有发布量，也不是必须赶出的周更 KPI。如果只有两篇达到质量要求，就先呈现两篇，不复制卡片充量。

2026-10-27 起，内容分为三层，深度标准写进测试闸门（`scripts/content.test.mjs`）：

| 层 | 形态 | 最低标准 |
| --- | --- | --- |
| 存量 | 词条式指标（`format: entry`） | 基础解释 + ≥3 条指标分工 + 过程链 + 来源；用于搜索与查表。当前 9 篇指标均已升级为深度长文，版式仍保留给只承担查表功能的短条目 |
| 深度 | 指标长文（`format: article`） | ≥4 个分节、正文 ≥900 汉字、≥4 条真实常见问题、≥1 张机制图、每条事实段落有来源编号。当前 9 篇指标全部达到 |
| 编辑 | 身体与日常故事（`kind: story`） | 同上，且不使用指标分工/过程链模板；主推发现页 |

「常见问题」不能由指标名称自动生成（禁止 `如何理解…？`），答案也不得与正文逐字重复——这是本轮内容深化的直接原因：旧版问答只是把同一段指标说明抄了一遍。

优先考虑这些**编辑提问示例**，不是已核对的医学结论：「为什么爬楼后会明显感觉心跳？」「肺里和血液之间发生了什么？」「一个体检指标的名字到底在描述什么？」「为什么看同一张身体示意图，成年人和孩子可能理解得不同？」最后一题涉及成长类解释时须先核定范围和相应专业支持。每篇需有鲜明但准确的问题、能自证价值的首图/首段、按实际题材选择的图文节奏、清楚的来源/更新与相关下一篇；**不套统一五段课件，不靠恐吓标题抢点击**。

| 内容层级 | 常见形式 | 制作方式与质量关口 |
| --- | --- | --- |
| A 日常机制/基础概念 | 故事式问题、简化结构图、前后对照 | 核对每个关系和措辞，采用有授权的图片/自制示意；不把示意图当诊断标准 |
| B 常见指标/疾病基础 | 项目是什么、何时需咨询专业人士等非个体化解释 | 与原始来源逐条对应；阈值、疾病、治疗、药物等新增高风险说法有相称专业复核后再发布 |
| C 儿童心理成长/个体建议 | 年龄阶段或发育主题 | **不在首期开放**；儿童发展专业协作、适用人群和错误理解风险未解决前不发布判断性内容 |

最低编辑闭环：问题与目标读者 → 可靠来源及具体段落 → 脚本/图示及许可 → 将结论和限定条件放在同处核对 → 发布当前版本 → 反馈、勘误与撤回。参考 [CDC Clear Communication Index](https://www.cdc.gov/ccindex/tool/how-to-use.html) 检查表达清楚与主信息；参考 [WHO 社交健康信息可信来源原则](https://www.who.int/teams/digital-health-and-innovation/digital-channels/phase-ii--global-principles-for-identifying-credible-sources-of-health-information-on-social-media) 考虑来源与可信性。这些工具**不能替代专业判断或直接授权搬运素材**。AI 可辅助改写非医学措辞、生成构图草图，不能当事实来源、自动编造药效/数值或冒充专业审校。内容安全是编辑底座，不是首页的考试或「打分」玩法。

## 6. 功能优先级与工程解法

| 阶段 | 必须交付的产品能力 | 解决方案与保留边界 |
| --- | --- | --- |
| 首版 P0：可读可找 | 精选有限首页、真实图文详情、搜索/指标直达、专题仅有内容时可见、链接分享、来源/更新时间/纠错 | 优先复用现有 CMS/发布快照、SSR、搜索和分享；先人工编排已发布内容，卡片不创造第二份医学事实。旧 URL、撤回即不可读、正式/演示隔离及 `noindex` 不变 |
| P1：有库存再改善 | 真正可维护的系列、按需的图集或可控动画、编辑工具支持封面/图注/排序 | 只有人工编排变成瓶颈时才做策展模型/新 API；卡与正文绑定同一发布版本；没有稳定作品不建个性化推荐和无限分页 |
| P2：有运营能力才评估 | 专题扩展、订阅/关注、选题反馈或有限评论 | 评论要有人持续治理隐私、错误建议、广告和纠错；没有人负责就只允许编辑收集选题，不开论坛/问诊 |

工程在现有 [架构](architecture.md)、[内容平台](content-platform.md)和[公开页面渲染](public-rendering.md)上实现首页、详情、内容服务与 SSR：首页卡片必须引用已发布的同版本内容，撤回后不可继续展示，不能从草稿复制出第二份医学事实。首版完成标准是：真实内容足以支撑非空首页；直达/搜索/分享在手机上可用；编辑事实、图片权利和发布版本一致；失效内容不会留在首页；无图/失败/无 JS 仍可读；旧版可回退。工程测试证明功能正确，**不宣称证明市场欢迎**。不因孵化期缺用户数据而停工，也不把对规模的期待当成工程验收。

## 7. 交付顺序：从纸面决策到可用版本

1. **范围冻结（产品负责）**：确认一个主叙事「身体与日常」、首版必须有的两条路径和不做范围；登记已有内容能否公开、可用图片许可、维护者每周可投入的编辑时间。没有调查不妨碍冻结范围。
2. **样板与内容库存（编辑/设计负责）**：制作一篇完整的主图文及同主题相关篇，给首页、详情、搜索三种密度的真实文案/图；再补到能支撑有限列表的 4–6 篇。没有专业协作就先选基础题，不给高风险内容赶进度。
3. **页面重构（工程负责）**：只把首页从任务入口改成编辑精选的图文发现；详情按真实作品排版，搜索与旧链接保留。先复用现有发布快照与路由，不为新列表提前建设策展后台、算法推荐或分页系统。
4. **发布验收（共同负责）**：手机/微信内阅读、分享直达、大字/图片失败、来源和限定条件、撤回与缓存、正式/演示通道隔离、回滚逐项通过。发布后才观察自然流量与反馈，调整选题和排版，**不把未来用户调研前置为项目封锁条件**。

以后若能取得真实使用数据，关注的是：文章是否被打开并读到有用部分、搜索是否命中、真实分享/保存与返回、单篇制作/更新成本、错误反馈处理时间。先建立事件定义和隐私边界，再根据真实基线设指标；**当前不填造留存率、阅读完成率或“几周达到 PMF”的数字**。没有初期流量时按编辑产能和产品完整性做决策，而不是给 0 样本算转化。首期也不预设广告、带货或咨询收入：当内容可信性尚未建立时，把商业导流当首页目标会与编辑边界冲突，商业方案另行决策。

## 8. 哪些判断仍不能保证；什么情况要改方向

- 「图文易读、有人想转给家人」是设计推断，不是用户结论。若未来实际只发生一次性搜索，强化目录和索引，不再硬推信息流。
- 「小团队能持续制作」未知。若单篇图解成本超出维护时间，减少栏目、复用合法图示模板或寻找合作者；**不能降低事实核对和版权要求**。
- 没有已证实的独家功能或医生资源。不称「最专业社区」；长期差异只能靠作品库存、表达质量、可回查的修订与读者信任慢慢累积。
