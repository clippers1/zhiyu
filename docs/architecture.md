# 知愈：内容与多端架构

## 当前实际完成的范围

读者界面使用 React，完整部署由 Next.js 输出 HTML，Vite 保留离线演示。当前有 3 个指标专题、5 个器官专题；平台包含 Payload CMS + PostgreSQL、后台成员登录及正式/演示内容 API。没有读者账号、个人体检报告处理或真实医学审校记录。平台的实际流程与边界见 [内容平台说明](content-platform.md)。

- `backend/`：来源、知识、审校、修订、发布入口与审计；公开 API 仅读取显式发布快照。
- `0.0.1-beta.3` 增加私有纠错队列与凭码查询/删除 API、来源复核排期和后台维护待办，见 [纠错与来源复核](feedback-and-maintenance.md)。
- `0.0.1-beta.4` 通过 Next.js 服务端渲染公开页面，共享根目录 React 源码；发布快照、正文 HTML 与元信息按请求生成，见 [公开页面渲染](public-rendering.md)。
- `public/content/index.json`：离线演示摘要目录与初始迁移数据，不含专题完整正文。
- `public/content/indicator/*.json`、`organ/*.json`：每篇正文独立加载，包含结构化来源与版本。
- `src/services/content.js`：内容访问层，提供 `list` 和 `get`。本地与远程模式使用同一契约。
- `src/components`：首页、目录、文章、器官、搜索与来源显示分别维护。
- 当前开发版本使用 History 路由，支持刷新、浏览器返回与独立文章链接，例如 `/article/glucose`；旧 Hash 链接由浏览器兼容转换。`0.0.1-beta.1` 标签保留改造前实现。

## 内容增长到数千、数万条时

当前列表最多展示 6 条，详情按需获取；10,000 条**合成摘要**用来验证分页和筛选正确性。这不是生产环境的负载或性能保证。

本地模式仍需要下载整个摘要索引，并在浏览器里搜索。API 模式已实现数据库摘要搜索、分类和分页，配置 `VITE_CONTENT_API_BASE_URL=/api/demo` 或 `/api/v1` 选择集合；前者始终标明待审校，后者只展示正式发布修订。当前检索不是中文分词或语义搜索。

建议生产结构：共享内容库 → 内容管理与医学审校 → 内容 API → H5 / 小程序 / App。起步可用 PostgreSQL + 一个 CMS；摘要、分类、标签、器官关联和来源关系入库；图片与动画存对象存储，通过 CDN 加载。按真实查询性能决定是否引入专门的中文检索服务，不在原型阶段预先堆叠基础设施。

本版已实现服务端查询与分页、版本发布与回滚、审核权限和无缓存公开接口；来源变化由人工登记，到期在后台待办提醒。仍需补齐真实医学审校、持续执行的来源复核、自动化备份策略和真实设备性能基线。个人报告与读者账号是独立阶段，需要新的数据模型与存储策略。

## API 契约

`GET /content?kind=indicator&query=血糖&category=metabolism&cursor=...&limit=6`

可选参数：`kind`（indicator / organ）、`query`、`category`、`cursor`、`limit`、`featured=true`、`ids=glucose,pressure`。传入空 `ids=` 表示空收藏，必须返回零条，而不是全量数据。分类应根据内容类型返回，不能根据当前搜索结果任意丢失分类选项。

```json
{
  "items": [
    {
      "id": "glucose",
      "kind": "indicator",
      "title": "血糖",
      "subtitle": "…",
      "english": "BLOOD GLUCOSE",
      "icon": "droplet",
      "color": "orange",
      "number": "01",
      "tags": ["空腹血糖"],
      "category": "metabolism",
      "referenceCount": 4
    }
  ],
  "total": 1,
  "nextCursor": null,
  "categories": [{ "id": "metabolism", "name": "营养与代谢" }]
}
```

`GET /content/indicator/glucose` / `GET /content/organ/heart`：返回对应 JSON 文件的结构。不存在时返回 404。游标在 UI 中视作不透明字符串，远程服务可使用稳定排序键分页。本地模式使用偏移量模拟，不承诺并发写入下的一致分页。服务端应限制页大小，返回的列表不应携带完整正文。跨域部署须配置 CORS。

## 来源、版本与审核

每篇记录包含 `version`、`updatedAt`、`reviewStatus` 与 `references`。每条来源有 `id`、原文标题、发布机构、链接、支撑的知识范围、语言与核验日期；指标的段落和指标解释用 `sourceIds` 关联引用。核验日期表示本次检查链接与相关原文的日期，不代表文献发布日期、完整系统性文献审查或医学审校。

当前来源来自 WHO、NIDDK、NHLBI、NLM/MedlinePlus，均是机构健康教育资料。没有把宽泛的机构首页当作某条具体诊断阈值的依据；不使用国际页面里的单一阈值作为中国用户的通用诊断标准。所有记录仍标为 `pending`，未冒用医生或机构背书。

正式内容工作流：草稿 → 来源核对 → 专业人员审校 → 创建不可变修订 → 发布入口。`reviewed` 已要求绑定审核人、时间、正文及来源指纹；来源状态纳入审校检查，到期日期只驱动后台待办。正式 API 只返回已审校发布快照，演示集合单独隔离。新增诊断标准、数值阈值、适用人群时，仍需保存指南版本、地域、条件、单位与证据定位并完成实际审校。

## 移动端与渠道路线

| 渠道       | 可以复用                                  | 仍需实现                                                                                                                   |
| ---------- | ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 移动 H5    | 当前 React 页面、JSON/API、来源模型、路由；已完成 HTTPS 部署 | 真实手机与微信内置浏览器验证                                                                                   |
| 公众号     | H5 内容链接、文章链接、统一内容服务       | 公众号入口配置；自定义微信分享卡片需要 JS-SDK 及服务端签名，并受账号/域名配置限制                                          |
| 微信小程序 | 内容模型、文案、来源、接口、信息架构      | 独立客户端；React 团队可评估 Taro；DOM/CSS、内联交互 SVG、路由、存储和分享需平台适配，外部来源也要适配小程序能力与域名限制 |
| App        | H5 + 内容 API                             | 可用 Capacitor 封装起步，补原生分享/导航、安全区、构建签名与商店流程；深度原生交互再考虑 React Native 等方案               |

公众号文章适合承载精简图文并引导进入 H5/小程序，不能直接承载这套网页中的所有交互动画。公开知识页已有正文 HTML 和逐篇分享元信息，当前采用无缓存动态 SSR，SSG/ISR 暂缓。微信自定义分享卡片仍需按平台要求接入 JS-SDK；当前系统分享/复制链接仍只是链接分享，不代表已完成真实平台分享验收。

最新规划将来源库、CMS 与医学审校流程提前，与移动端阅读体验并行推进，再扩展完整主题、公开页面预渲染和外部渠道。详见 [知识平台](knowledge-platform.md)、[渲染决策](rendering-and-routing.md) 与 [实施计划](roadmap.md)。现在没有生成 App 安装包、小程序工程、PWA 离线缓存或公众号接入。

## 验证

- `npm run test:content`：内容引用完整性、10,000 条合成摘要的筛选分页、远程适配器参数、失败重试。
- `npm run test:ui`：启动 5173 开发服务后执行；检查桌面/移动端、来源定位、浏览器返回/刷新、收藏、搜索、分页、错误重试与按需请求。
- `npm run build`：生产构建。
- `npm run test:routes`：History 地址解析、错误路径及旧 Hash 链接转换。
