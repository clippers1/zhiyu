# 场景入口与查找路径（0.0.1-beta.6）

## 本轮交付

首页先按读者任务提供三个入口，不增加账户、个人报告、症状诊断或自动推荐：

| 读者目的 | 入口承接 | 可完成的下一步 |
| --- | --- | --- |
| 查体检单上的术语 | 指标目录的查找框 | 输入名称/缩写，或点击现有专题中的标签示例，进入文章、目录与来源 |
| 认识一个器官 | 首页当前可用的器官列表 | 选择专题，了解器官及可用的关联指标 |
| 找回读过的知识 | 收藏页 | 查看已有收藏、管理默认关闭的本地阅读记录 |

跨页入口使用真实链接，页内入口使用普通锚点；可用键盘、新标签页或关闭 JavaScript 后打开。禁用脚本时仍可浏览 SSR 目录与器官链接，但筛选、收藏和本地记录管理依然需要脚本。

## 内容可用性与医学边界

- 器官列表来自已发布集合的摘要，SSR 同时预载首页的指标与器官摘要，不下载全部文章正文。人体图保留结构示意，但不可用的器官不再支持点击或键盘进入。
- 器官页人体图也以当前目录为准。首页下方器官按钮进入实际可用条目，入门导览结束后进入指标目录，不再强制打开默认心脏专题。
- 器官目录单次最多 24 项；当前只有 5 个专题，扩大到更多条目前应增加分页或独立目录。全局 `/organs` 仍兼容旧默认心脏入口；如该专题已撤回，会返回真实 404，不回显旧内容。
- 无可用内容时显示边界说明，隐藏无内容承接的阅读卡片；客户端请求失败时可重试。SSR 数据库失败仍按现有规则报错，不使用旧 JSON 兜底。
- 不新增医学结论、阈值或专业审校。术语示例取自当前目录页内容的标签，不代表热门程度、完整覆盖或适用于个人的推荐。
- 入口只做导航，不自动开启阅读记录，不收集报告或新增分析埋点。已有接口会处理普通内容查找请求，不宣称服务器看不到访问。

## 自动化验证

```sh
# 静态开发服务：包含空目录、撤回条目模拟和失败重试
PLAYWRIGHT_BASE_URL=http://localhost:5173 node scripts/discovery-smoke.mjs
# 完整站点：增加无 JavaScript 入口测试
TEST_SSR=true PLAYWRIGHT_BASE_URL=http://localhost:3108 node scripts/discovery-smoke.mjs
```

测试三条查找路径、术语示例、文章来源定位、阅读记录默认状态、键盘进入和 320/390/768/1440px 布局。`backend/scripts/rendering.test.ts` 在独立测试库中验证器官撤回同步影响首页 HTML、列表和图形入口，不允许指向生产数据库。

这些检查不等于真实用户验证。下一步建议以 5–8 位读者分别完成“查一个缩写、从器官找到关联知识、收藏后再次打开”任务，记录困难与错误理解；需由真实参与者完成，不预填成功率。

## 剩余工作

场景入口的工程实现到此形成可测试路径。后续优先补 CI 回归与定时备份/恢复保障；正式医学内容仍依赖来源许可核查、编辑与合格医学审校，分享效果仍需真实手机和微信验收。
