## 1. 参考对象与证据边界

具体迁移原则：复制**信息关系**（搜索优先、分类渐进、重点答案与相关项有强弱、正文可信信息可查），而不是复制组件的像素位置、阴影、图标数量或色块比例。2023 年的 iOS App 截图也不能直接当作今日的移动网页规范。

把截图当作版式样本而不是成功证明，还能看到四种可迁移的**空间关系**：① 030 首屏按“搜索窄条 → 服务大入口 → 分类小入口 → 整宽横幅 → 内容流”逐级降低入口权重；知愈需要借的是**先完成查找、再决定浏览**，不是照搬服务模块的高度。② 003 用一条占较大面积的重点内容和下方连续的普通列表拉开主次；知愈首屏只留一条值得展开的回答，其余问题用紧凑行列出。③ 004 在话题索引与帖子流之间插入整宽专题，让“选方向”和“读单篇”有过渡；知愈用已有来源支持的路线替代横幅，不靠空白填充不存在的业务。④ 039 的标题、署名、推广图、正文之间出现了明显断点；知愈**不能让来源标识或大图把问题与答案隔开**，核对状态应靠近标题，答案紧随其后，图只负责解释答案。这些是对截图的观察和本产品取舍，并非对用户行为的实测结论。

## 2. 当前基线与要解决的问题

截至本文撰写时，工作区可见 9 篇指标、5 篇器官；问题式首页、指标列表、搜索、详情、专题路线、心肺互动、来源/版本和分享已具备代码入口。`H02/H03` 的本地改动处于**未提交工作区**，线上是否部署须单独核验。旧文档里关于收藏、继续阅读和读者纠错的能力描述与当前代码可能不一致，重构不能依赖它们作为“已上线基础”。

根问题不是“只有三个底部导航，所以显得简陋”，而是：

1. 目前多数问题入口指向同一篇指标文章；从首页到详情有路径，但**不同生活情境需要怎样接着读**尚未形成稳定的内容簇。
2. 指标、器官、专题路线各有页面，但“我想理解的这个疑问”与“下一步相关知识”之间缺少统一、可维护的关联规则。
3. 图文样板、静态分镜、完整文字及来源许可没有构成可批量复用的生产单元；靠增加首页卡片不会自然增加有用内容。
4. 婴幼儿发展、脑科学和慢病目前是候选方向，缺来源与专业复核时不能通过增加空导航营造业务丰富度。

目标体验：**有事可查，有路可逛，看完能继续理解；找不到时诚实告知；医学风险不因功能丰富而失控。**

| --- | --- | --- | --- |
| 首页 `/` | 连续列出 9 个形态相近的问题，随后又推荐其中 3 个，再堆 5 个器官入口；价值层级被重复卡片冲淡 | 页面约 4133px 高；问题卡摘要约 11.5px、首页导语约 13.5px | 首页只留 2–3 个**不同任务**的入口和 1–3 个精选问题；全部 9 个归入目录；器官只留一条图文专题入口 |

绿色“看起来太多”可以是视觉疲劳的信号，但**眼下不先换色**：先修复信息重复、文字偏小、内容顺序和图文脱节，再用读者任务检验改版。如果随手换色，只会得到同样结构的另一套皮肤。

## 3. 产品结构：三层而不是十几个并列频道

### 3.1 第一层：按任务进入（导航）

首阶段保留当前“发现 / 体检项目 / 认识身体”的可用路径和旧 URL，不先增加第四、第五个底部标签。首页负责“查一个问题”；体检项目页负责“按名称/分类找”；认识身体负责“图文看过程”。**专题路线**作为现有页面，在首屏问题卡和文章末尾自然接入，而不是反复占据首页主视觉。

当至少两个非指标主题簇持续维护、用户观察证明会主动跨主题浏览时，再评估导航升级为“发现 / 查知识 / 专题”；“我的”仅在明确需要且有隐私设计的收藏或阅读记录确实上线后出现，不用空页面占位。

### 3.2 第二层：按情境聚合（策展）

同一篇知识可出现在多个**情境入口**，但正文只维护一份：

| 情境入口（编辑策展，不是医学人群判断） | 可用内容示例 | 进入后应得到 |
| --- | --- | --- |
| “拿到体检单” | 血糖、血脂、血常规、肾功能等已发布专题 | 查术语 → 看含义/局限 → 查看关联项目 |
| “想了解长期健康” | 血压、血糖、血脂的基础问题；慢病内容待专门复核 | 从基础概念理解关系，不推断个人患病风险 |
| “想知道身体怎么运作” | 心、肺互动及其他已开放器官 | 静态图 → 可控步骤 → 对应文字与来源 |
| “我对脑与行为感兴趣” | 暂为选题池，不公开空频道 | 有来源、主题规模与维护能力后才成为专题 |
| “陪宝宝成长” | 暂为独立研究和专业复核选题池 | 不用观察清单对单个儿童作判断 |

入口是否显示取决于**已发布且可读的关联内容**，而不是预先把五种情境全部放上首页。情境标题不得比对应文章承诺得更多。

### 3.3 第三层：按内容类型深化（知识网络）

内容类型区分“**项目/术语**（是什么）”“**问题**（读者问什么）”“**原理/器官**（为什么）”“**专题路线**（依什么顺序理解）”。一个问题可指向一篇项目详情并串联关联问题，但不能复制多份互相不一致的医学正文。知识关系至少支持：问题 → 所属项目；项目 ↔ 项目；项目 → 已发布器官；专题路线 → 一组版本明确的知识。所有关联须可撤回，不产生失效入口。

## 4. 功能搭配：保留、补齐、暂缓

| 能力 | 当前基线 | 重构建议与依赖 | 优先级 |
| --- | --- | --- | --- |
| 搜索 + 分类 + 常问问题 | 有问题式列表、术语搜索和筛选 | 三种入口共享内容摘要；同义词/缩写有明确映射；未命中仅建议真实内容 | P0 |
| 情境策展与专题路线 | 有单指标阅读路线，跨主题策展不足 | 编辑选择真实已发布内容组装路线；首期只做“看懂体检单”一条任务线 | P0 |
| 图文知识模板 | 指标以文字为主，器官有局部互动 | 静态图解优先，分步其次，动画只用在过程；逐幅来源和完整文字同步 | P0 |
| 关联阅读 | 有指标 ↔ 器官关系 | 加读者看得懂的“为何相关”和下一篇理由；仅链接已开放内容 | P1 |
| 轻量术语对照 | 有常见项目和术语解释 | 在详情里做可追溯的对照图/折叠解释，不做输数值判风险的小工具 | P1 |
| 自愿纠错/没找到反馈 | 现有读者反馈能力有版本差异 | 先核实当前线上能力；若恢复，最小化采集，不要求报告/联系信息 | 条件触发 |
| 收藏/继续阅读 | 当前读者实现和历史文档不一致 | 验证跨次回访需求后再做，默认不记录健康兴趣；先不承诺账户 | 条件触发 |
| 在线问诊、社区、商城、等级 | 不属于现有定位 | 不因参考 App 有类似类目而复制；若未来业务改变，单独立项 | 不做 |

**丰富度衡量的是任务闭环和知识可达性，不是卡片总数、频道总数或动效总数。**

## 5. 页面组成与交互规格

下述为**内容与布局顺序**，不是颜色/字体风格稿；页面无内容时缩减区块，不填占位卡。

### 5.1 发现首页：解决“我现在从哪开始”

手机从上到下：简短品牌名/任务句 → **唯一的主搜索** → 两个不同任务的入口（按项目查 / 走专题；有内容才显示）→ 1–3 个已发布常见问题 → 一个可用的情境/专题入口 → 认识身体入口（有图文内容才显示）→ 全站说明。专题若已在任务入口完整呈现，次屏不再重复一张专题推荐；桌面可将主搜索和一个真实专题预览并排，其余顺序不变；**不把大幅器官插画置于搜索之前**。

对照可见的 001/030 首页，设计上刻意缩减“快捷服务”与信息流密度，不是因为它们无效，而是知愈没有问诊、预约或持续更新的帖子业务。首屏建议只出现一处搜索、一条能直达正文的真实问题，以及最多两种**不同任务**入口；“首屏”是用真机验证的意图，不靠固定 844px 截断、缩小字体或在系统放大文字时强塞卡片。同一问题不在搜索建议、瓷片区和推荐卡中重复出现三次。

- 主搜索明确是查术语和知识，不暗示能上传体检单。问题卡显示“问题、对应项目、一个有依据的一句话摘要、内容状态”；不是“今日热门”或“平台推荐诊断”。
- 情境入口按已发布内容组装。无慢病/儿童正式内容时不展示相应分类或“即将上线”空卡。
- 专题推荐只指向已有可读的路线；用户点击后能清楚知道需要读几步、可随时跳过。
- 首次访问、空专题、请求失败、撤回后的缓存必须分别设计；搜索与问题卡不会链接到被撤回的内容。

### 5.2 知识目录/搜索：解决“我知道一个词，但不知道归哪类”

搜索框常驻首区；其下是当前有内容的分类与按问题组织的结果。搜索结果显示命中的词及内容类型，区分“指标”“器官”“专题”，不把项目名称匹配伪装成对个人报告的解读。移动端筛选可横向滚动但不遮挡输入；分类标签数量来自已发布目录而非全部草稿。

可见的 003 百科页采用“搜索 → 类型切换 → 重点卡 → 相关条目”的顺序。知愈不照搬“医生/药品/医院”的分类，而是用“问题/体检项目/身体原理”区分结果，且重点卡只对应已核对的问题与答案；没有对应内容就不显示该分组。

未命中时给改写建议、真实可浏览分类与“仍没找到”自愿反馈（能力确认后才显示）；无内容、网络异常与输入法合成中分别有明确状态。正式站与离线演示使用同一结果排序规则或明确标注差异。

### 5.3 问题/指标详情：解决“我看到的项目是什么意思”

顶部：问题标题及紧邻的核对状态 → 一句话回答 → 与答案相连的必要限制。主体：可选主图/分步图及文字替代 → 核心解释 → 更完整的“不能据此说明什么” → 常见相关术语/项目 → 关联的身体过程。末尾：详细来源定位、适用范围、版本时间、相关问题和分享。**必要限制在首个答案附近就能看见，来源入口始终可查；详细出处可以在页末，不把风险信息藏到页末或悬停层。**

可见的 039 详情页把审核信息放在标题上方；知愈应沿用**位置而非结论**：分别写清“依据具体来源整理 / 专业审校 / 待核对”，不把第一种伪装为第三方医疗背书。035 的单条分享卡只借鉴“单一知识单元”形式，分享图和摘要仍须保留适用范围与指向完整来源的入口。

无图时完整文字依然成立；有图则每个箭头、数值、标签都要追溯视觉脚本卡，图下说明非真实比例/条件（如适用）。分步图提供“第几步、上一幅/下一幅、完整静态文字”；动画默认不自动播放。分享出去的摘要不得脱离限制条件，撤回后旧链接提示已不可读。

### 5.4 专题路线：解决“读完一篇之后怎么继续”

路线首页只展示已开放路线：一句任务描述、预计步骤数（不是阅读时长承诺）、覆盖问题、适用边界；点击后给出**起点 → 为什么看这一篇 → 可选延伸**。每步是独立可分享的知识页，跳过一步不会丢上下文，不设置答题、排名或“治愈进度”。编辑能撤下某一关联并检查路线是否仍成立；空路线不进入推荐。

### 5.5 身体原理页：解决“这个过程怎样发生”

保留心肺现有交互与结构图，先给可读的静态图和一句问题，再给可手动控制的步骤、每步文字和图示依据；关联到已发布的指标问题。没有可核对视觉素材的器官页只呈现文字/授权图，不为每个器官硬做动画。减少动态效果、键盘操作和移动端单列均作为必测场景。

### 5.6 未来疾病/脑科学/婴幼儿专题（不上首期空页面）

疾病页与普通指标页**不是同一风险模板**：解释适用人群、范围、常见误区及寻求专业帮助的边界，需要相应专业复核和服务端发布拦截；不做数值判诊断。脑科学先选“研究怎样解释某个现象”的低风险问题，明确证据和不确定性；不包装成改善记忆的疗法。婴幼儿内容区分发展观察和医学筛查，专业复核不足时仅为内部选题，不上线年龄判定、打分或发展风险结论。

### 5.7 通用排版规则：先定阅读逻辑，再定皮肤

下列是**知愈的设计起始值，不是对所有用户的科学定论或最终 CSS**；需在 320/390/430px 手机、平板、桌面及放大字号下核实。参考 App 的截图是视觉观察，不替代知愈自己的可用性测试。

| 尺度 | 先采用的布局约束 | 读者得到的好处 / 验证点 |
| --- | --- | --- |
| 页面容器 | 手机左右安全内边距约 16–20px；长文正文桌面上限约 680–760px；目录可放宽到约 1100–1200px | 手持易读，桌面长行不来回扫视；中文长标题自然换行，不写死两行 |
| 字级（中文） | 正文 16–18px；卡片问题 17–20px；大标题 26–32px；段落辅助 14–16px；来源元信息约 14px 起，可随“大字号”同比放大 | 当前卡片摘要 11.5px 偏小；不靠浅色/极小字区分主次。桌面可微调但不骤变 |
| 行距与行长 | 正文行高约 1.65–1.85；标题约 1.25–1.45；列表仅展示由已核对正文编辑出的简短独立摘要，优先写到两行内，不用 CSS 强行截断有医学意义的条件 | 长文和术语有可追踪的行序；在真实字体加载后看换行，避免英文缩写孤悬 |
| 间距节奏 | 以 8px 为基础，内容块内 8/12/16，卡片之间 16–24，章节之间 32–48；手机卡片内边距约 16–20 | 用空隙而非大量外框区分章节；连续同类条目可用分隔线而非每条浮起的卡片 |
| 操作尺寸 | 本项目目标为关键触控区域至少约 44 × 44 CSS px（初稿），图内热点可放大可点击区；键盘焦点明确 | 适合手指操作和字号放大；数字是本产品目标而非引用第三方最低标准 |
| 页内导航 | 主要内容只有一个 H1；H2 按阅读顺序划分“先看答案/看图/有哪些限制/继续读/来源”；手机底部导航不盖住正文或图的控制 | 不必猜跳转后落在哪里；直接链接和无 JS 场景也能按顺序阅读 |

**文字写法：**标题以读者问题为主，不用大写英文装饰词（当前首页的 `START WITH A QUESTION`、目录的 `TEST QUESTIONS` 可弱化或删除）；英文缩写放项目名旁作为检索辅助，不做卡片主标题。一个小标题只回答一个问题，图注写清“这张图解释什么/省略什么”。限制条件不得压成灰色小字或只放页面最底部。字体、品牌调性、颜色均**待定**；上表只决定大小、行距、空间关系。

**信息密度规则：**标准字号的首页首屏争取看见搜索和**至少一个可点的真实问题**；放大字号时优先保证文字完整，不强求同屏。首页不再把 9 篇相同样式的内容全部铺开，也不在下方重复推荐同 3 篇。目录列出全部已发布内容，数量增长到无法快速扫描时再评估分页/加载更多；详情只引导 1–3 个有理由的下一篇。某篇文章没有已核对主图就给可读的摘要，不用通用医学图来撑版式。内容增加时只扩目录和情境路线，首屏区块数量不随文章数线性增长。

无障碍验收分别覆盖 [W3C WCAG 2.2 重排](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)、[文字缩放](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html) 和 [目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) 的适用条款；健康图文的清晰度可参考 [CDC Clear Communication Index](https://www.cdc.gov/ccindex/tool/how-to-use.html)，但清晰测试不代替医学事实核对。

### 5.8 卡片的职责，而不是到处套一种卡

| 卡片角色 | 只回答什么 | 哪里用 / 不该放什么 |
| --- | --- | --- |
| 快捷任务块 | “我现在要查项目，还是沿专题阅读？” | 首页至多两项，动作文字清楚；不用问诊/预约图标冒充服务 |
| 主问题卡 | “这个问题有没有一句可信的答案？” | 首页仅精选 1–3 条，与目录指向同一正文；重点体现问题 + 已核对摘要 + 去向 |
| 目录行 | “这篇是不是我找的那项？” | 目录和搜索结果，以问题标题、匹配词和内容类型为核心；少用浮层/阴影，便于快速扫描 |
| 专题预览 | “沿着这条路能学到什么？” | 情境页或首页次屏，写范围/步骤和结束点；未形成路线时不出现 |
| 图解步骤 | “这一幅图实际说明了什么？” | 详情及器官页，图/短句/来源同步；不是与正文无关的装饰图 |
| 关联链接 | “为什么接着读这一篇？” | 正文末 1–3 条，附一句关联理由；不是随机猜你喜欢 |

同一内容在首页、目录、详情使用**不同密度的摘要**，但医学主张来自同一版本；摘要和主图不应在三处形成三个冲突的结论。来源核对状态是证据信息，不是营销徽章。

### 5.9 三个核心页面的无配色线框（按手机阅读顺序）

```text
发现页                        项目目录                       知识详情
┌品牌/一句任务说明   ┐       ┌返回  搜索项目     ┐          ┌返回           分享┐
│[搜索项目或问题   🔍]│       │[输入词或缩写]      │          │问题标题/核对状态 │
│[按项目查][看专题]  │       │[全部][有内容分类…] │          │一句话答案+必要限制│
├先回答一件事         ┤       │找到 N 条           │          ├解释图/文字替代   ┤
│问题？→答案一句→详情 │       │问题标题/命中说明  │          │图注/分步控制     │
├看看另一类知识       ┤       │一句摘要/项目名    │          ├不能说明什么     ┤

├认识身体（有则显示） ┤       │下一条/翻页         │          │来源/版本/纠错    │
└全局底栏           ┘       └全局底栏           ┘          └有理由的下一篇   ┘
```

再用同一批**已发布内容**制作 B 版“浏览优先”的首页线框：品牌/一句任务说明 → 一处搜索 → “常见体检问题”两条紧凑目录行 → “从一张体检单开始”单条路线 → 项目分类入口 → 全站说明。A 版（上图）以两种任务入口承接搜索；B 版先给能直接阅读的问题、把分类放后。两版**不改变医学文案、内容数量或配色**，否则无法判断布局差异；观察哪版让人更容易找到答案和限制，再选择哪版，不预设 A 版更好。若 B 版让“不知道术语”的读者找不到入口，可把“按项目查”前移，而非叠加第三个搜索框。目录和详情共用一套线框；首页顺序验证后，再单独测试目录结果行、详情图文顺序，不把 A/B 观察误称为全站验证。

**首页首屏布局顺序不能变成“品牌大图 → 9 个问题 → 3 个重复推荐”。**长页面只通过“更多项目/专题”逐层打开，不让用户为了找到第一条答案滑过营销或装饰区。**目录不是第二个首页：**不重复大幅首屏标题和品牌口号，进入后立即能筛选。**详情不是百科长卷：**标题和核对状态后先答题、说明必要限制，再有根据地给图与深入解释；已有心肺互动保留在适当的“理解过程”段。

桌面端遵守同一 DOM 阅读顺序：首页搜索和一条真实精选问题可双列，目录筛选位于结果上方或窄侧栏，详情长文单主列、目录/来源快捷链接可做窄侧栏。没有内容时不造空右栏；手机收成单列时操作顺序和朗读顺序保持不变。页面跳转使用真实链接，刷新与分享路径仍指向相同内容。

### 5.10 状态、检验和“大众接受度”的证据

| 必测状态 | 对应体验 |
| --- | --- |
| 无推荐内容 / 搜索未命中 / 专题撤回 | 隐藏空栏，清楚说明只是不收录此主题，不推断读者健康状况；给返回真实目录的路 |
| 加载中 / 接口失败 | 页面框架和标题稳定，必要时重试；不要在失败时用旧缓存冒充仍已发布 |
| 图像加载失败 / 减少动态效果 / 无 JS | 图解的文字与来源可独立阅读；不留空盒；非动效路径同样说清关键过程 |
| 大字号 / 长项目名 / 英文缩写 / 320px 宽 | 不横向滚动、截断医学限制或遮挡按钮；目录行可以变高，不强制一屏塞六条 |
| 直接打开深链接 / 浏览器返回 / 分享旧链接 | 保持阅读位置与对应内容版本正确；失效或撤回不悄悄跳去首页 |

“大众接受”不是视觉审稿人说好看：先用现有页面和 5.9 的 A/B 两版**灰度、不定配色的线框**做任务比较。第一轮拟观察 5–8 位读者，覆盖工作年龄读者、需要大字号的中老年读者、常替家人查知识者；尽量包含不同阅读习惯，样本只用于发现问题，不能声称代表所有人。任务用同一套实际已发布内容：① 不给术语，只说“我拿到体检单，不知道从哪里开始”；② 给出“血脂”，找到一句回答并用自己的话说出**不能据此说明什么**；③ 找到相关的下一篇和依据来源。轮换 A/B 顺序，观察首次点击、查找是否成功、误读、滚动回退、哪些字太小；记录原话而非只记“喜欢哪版”。**任何危险误解先修内容与图示，再复测**；比较前设定放行门槛：每类任务均能在不提示的情况下完成，重要限制不会被遗漏，且不产生尚未解决的危险误解；达不到就继续改版，不凭少量样本计算推广到大众的百分比。再用真机和微信内置浏览器检查 320/390/430px、文字放大、键盘/屏幕阅读器，并记录上线后自愿反馈；不能靠单张漂亮截图宣称普适。

## 6. 内容与后台重构前置条件

1. **一个知识事实，一份来源映射。**项目、问题、专题路线可复用已核对事实；新增问题摘要不得绕过正文来源和版本。专题关系需要指向当前可读版本，撤回立即失效。
2. **编辑策展是独立数据，不是硬编码假入口。**情境/专题配置至少有标题、适用读者问题、关联内容 ID、人工排序、上线条件及撤回状态；缺内容时自动降级为目录入口，不编造“热门”。先用小规模可审核配置验证，再决定是否 CMS 化。
3. **媒体有单独的权利与科学性记录。**每张图/每一动画步骤记录所表达的主张、来源定位、图示简化、授权、署名位置、替代文字、版本；不能因为底图可用就认为新箭头/标签正确。
4. **风险等级驱动发布。**基础术语/结构沿用当前来源整理流程；涉及疾病、数值标准、诊疗、特殊人群、儿童发展改走独立专业复核和服务端拒绝绕过规则；没有复核者就停留在内部选题。
5. **隐私最小化。**不需要上传体检报告或用户账号才能浏览内容。若收集未命中词/阅读偏好，先有告知、匿名化/本地存储策略、删除方式；不要默认留存可能包含个人健康信息的原始搜索词。
