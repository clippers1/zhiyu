# 知愈成果路线图

更新：2026-09-19。当前实现基线：`0.0.1-beta.14`。

`0.0.1-beta.14` 进展：P0 来源整理发布和 P1 心脏循环样板已完成；P3 的第二主题“呼吸与肺泡气体交换”也已完成工程实现，证明同一互动模式可以复用。基础知识不要求独立专业审校，旧版审校能力仅兼容保留。P2 的真实手机/微信与 5–8 位读者理解任务仍未完成。

当前方向：**可靠医学知识集合 + 可视化互动展示**。本文件取代旧版以“扩内容后台 → 逐篇独立审校 → 完整医学内容库”为主线的执行顺序。产品依据见 [产品规划](product-plan.md)，首期任务见 [可视化互动方案](visual-learning.md)。

## 1. 从哪里继续

已完成的基础能力不重做：

| 范围 | 已实现 | 仍需区分的边界 |
| --- | --- | --- |
| 访问与部署 | History、Next.js 动态 SSR、metadata、真实 404、Docker/HTTPS | 不代表真机体验或性能目标已全部验收 |
| 内容维护 | CMS/数据库、来源库、来源整理发布、回滚/撤回、审计、纠错与来源待办 | 心脏与肺完成来源整理；旧内容未自动晋级 |
| 阅读闭环 | 场景入口、搜索、专题路线、收藏、大字号、继续阅读、分享卡片 | 实际理解、回访与分享效果尚未验证 |
| beta.12 | 指标原文速览、折叠术语解释、三类阅读反馈 | 不是独立 FAQ 库，也不是新的可视化专题 |

现有内容规模为 3 个指标 + 5 个器官。心脏和肺已按具体来源与表达逐项整理；其他旧内容仍需按同一标准处理。独立专业审校不是基础知识发布或后续迭代指标。

历史版本完成情况见 [CHANGELOG](../CHANGELOG.md)，操作说明仍以各功能文档为准。不按代码量编造全项目完成百分比。

## 2. 新旧优先级对照

| 原先的重点 | 现在希望得到的结果 | 取舍 |
| --- | --- | --- |
| 每篇正式内容都要独立专业审校 | 成熟基础知识按可靠来源整理后发布 | 独立审校不是必经流程；疾病、数值与个体诊疗暂不做 |
| 先凑齐约 20–30 个主题页 | 一个专题能让用户讲明白一个过程 | 不设文章数量门槛 |
| 搜索与阅读按钮持续扩展 | 用户通过图文和动手操作看懂身体机制 | 复用现有功能，主要投入专题本身 |
| 扩展后台和内容运营流程 | 单人或小团队维护得动 | 后台只补支撑专题与正确发布所必需的能力 |
| 扩 App、小程序、视频渠道 | 先在手机网页完成一次有价值的学习 | 新渠道和视频按验证结果再投入 |

## 3. 阶段总览

使用“现在 / 接下来 / 后续 / 条件触发”表达顺序，不承诺固定日期或预先分配版本号。每次有可交付范围并验证后再确定版本。

| 阶段 | 希望获得的用户/维护结果 | 主要交付 | 完成信号 | 依赖 |
| --- | --- | --- | --- | --- |
| P0 · 已完成：来源整理与发布规则 | 维护者可直接维护成熟基础知识，不被不必要的审批阻塞 | 样板知识点/来源清单、风险边界、新发布路径与状态迁移 | 基础内容可显式发布；未核对和越权被阻止；旧内容不自动晋级 | 具体来源、许可核对及后端规则改造 |
| P1 · 现在主线：互动样板 | 普通读者能跟随心脏循环图理解结构和顺序 | 分步图、点击解释、可控动画、同步文字、来源、理解题、已有收藏分享接入 | 无提示完成关键操作；脚本/动画与来源一致；手机及无动画路径可用 | 可先做脚本与静态样板，公开发布依赖 P0 |
| P2 · 接下来：验证并修正 | 找出哪里没看懂，确定互动是否真的有帮助 | 5–8 位自愿读者任务观察、真机/微信检查、问题修复、制作成本基线 | 无未解决的阻断问题或重大误解；有可追溯观察记录 | 样板可试用、真实参与者和设备 |
| P3 · 工程完成、待验证：复用到第二主题 | 用户能从循环过程自然衔接到肺泡气体交换 | 肺部六步互动、共享组件、来源与理解题 | 已复用主要展示模式且自动回归通过；真实理解效果仍归 P2 验证 | 具体来源与素材已完成，真实参与者待安排 |
| P4 · 条件触发：补媒体和渠道 | 图文/交互仍无法解决的问题得到更合适的解释 | 有字幕/文字稿的短视频，或有明确需求的渠道增强 | 有授权、移动端可用、能证明解决具体理解障碍 | 用户反馈及制作/维护能力 |

P0 只做支撑首期的最小改造，不能演变成另一轮平台建设。P1 的脚本、静态图和交互开发不等待全库内容整理；若发布规则尚未验收，样板只在明确标识的预览/测试环境验证。

## 4. P0 的具体实施边界

### 来源与表达

- 为首期逐条填写“知识点—来源定位—使用方式—示意简化—核对日期”，模板见 [首期方案](visual-learning.md)。
- 把基础解剖/生理与诊断、治疗、数值判断分开；后者不混入首期。
- 同一维护者可以完成基础内容整理与核对；未解决的专业疑点缩减或延后，不以流程放行替代判断。

### 发布状态与兼容

`0.0.1-beta.13` 起正式集合支持基础知识来源整理，`0.0.1-beta.14` 已复用到第二主题；以下约束已进入数据模型和隔离流程测试：

1. 分开表达发布状态、来源核对、专业审校，给低风险内容明确的发布资格；不是简单删除审校检查。
2. 核对记录绑定内容与来源版本；内容/依据变更后重新判定，不继承失效的核对信息。旧发布快照仍可追溯。
3. 只有授权维护者能核对和显式发布，匿名不能写入；未完成来源、许可与表达检查的草稿不得沿此路径上线。高风险范围不因选择“基础知识”而自动放行，需人工判断内容与标签一致。
4. 保留真实医学审校记录及其不可伪造性；“来源整理”不能冒用“专业审校通过”。
5. 逐篇迁移旧内容，稳定 ID、链接、收藏和反馈版本绑定保持兼容；不批量转换现有 `pending`。
6. 同步公开 API、SSR、徽标/说明、分享卡片与 SEO 规则。旧演示保持 noindex；新内容只有完成显式发布及 SEO 验收后才纳入 sitemap。
7. 用隔离数据库覆盖来源整理发布、未核对拒绝、越权拒绝、变更失效、真实审校、回滚、撤回和旧内容兼容；完成备份与回退方案后才部署。

角色是工作职责而非新增岗位：维护者负责来源与脚本，工程负责规则与展示，真实读者参与体验验证；专业人员仅在相应内容确有需要时参与。

## 5. 紧接着执行的任务包

| 顺序 | 工作包 | 可验收产物 |
| --- | --- | --- |
| 1 | 定义心脏专题的学习问题、来源及简化边界 | 一个来源映射完整的脚本；不含疾病判断、用药或个人数值输入 |
| 2 | 实现 P0 最小发布规则，并完成静态分步样板 | 隔离流程测试；结构图、步骤说明和无动画阅读路径可核对 |
| 3 | 加入点击结构与播放/暂停/逐步控制 | 图文状态同步，键盘、触屏、减少动态效果可用 |
| 4 | 接入来源、关联阅读、收藏分享与纠错 | 新旧链接/内容版本一致，无空入口，撤回后停止公开展示 |
| 5 | 自动回归、真实设备与读者任务验证 | 检查记录、已知限制、修复结果；未完成的人工项如实标注 |
| 6 | 达到公开验收后交付 | 更新功能文档与版本记录，按实际范围提交版本，部署保留回退 |

样板可以分批交付，不必等待视频或第二主题。真实用户验证未完成时，可明确标记为实验性 Beta，不声称已证明教学效果。

## 6. 进度与验收方式

用“脚本核对完成 / 静态样板完成 / 交互完成 / 工程验证完成 / 真实读者验证完成”分别记录，不将五项混成单一完成率。

- 学习：读者能按预设要点复述基础循环路径，且不产生危险误解；先记录基线，再决定后续目标。
- 可用性：小样本目标为至少 4/5 位试用者无需提示完成选结构、控制步骤、查看来源；是局部检查门槛，不是总体用户成功率。
- 技术：320–768px 布局、触屏/键盘、减少动画、无 JS 图文、直达刷新与回退、来源链接和内容撤回通过检查。
- 维护：记录首个主题实际制作成本，第二主题再验证是否能够复用；不先承诺批量生产速度。
- 性能：首期不加载视频或 3D 运行时，比较改造前后资源量与真实设备交互体验；先测基线再设预算。

## 7. 继续保留与明确暂缓

继续保留：必要测试、版本记录、部署前备份、可回退部署、来源与纠错维护。Docker 构建继续遵循 [现有空间保留策略](public-rendering.md)，不为文档改动构建镜像，不扩大清理到其他项目或数据卷。

暂缓：后台大改、复杂搜索、自动抓取全文、AI 医学摘要/诊断、读者账号与云同步、社区打卡、报告/OCR、App/小程序、付费功能、3D 人体和全站视频化。CI 和定时异地备份仍是交付保障候选，不抢占首期互动样板主线；开源许可证另行决策。

**下一步优先完成心脏与肺两个主题的真机、微信和读者理解观察，根据共同问题修正共享组件；不扩建医学编辑运营体系，也不以独立审校数量衡量进度。**
