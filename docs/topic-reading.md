# 专题阅读路线

版本：`0.0.1-beta.8`。

## 读者可以做什么

- 从首页当前可用的精选指标进入 `/topics/:id`，先看阅读顺序。
- 从指标概念读到该内容已有的关联器官，再回到指标的来源、适用范围、版本与审校记录。
- 从指标页顶部或结尾回到路线；器官页末尾可选择关联指标的路线。
- 跳过不关心的步骤，直接打开任意链接；链接支持刷新、新标签页和服务端无 JavaScript 阅读。

路线不要求打卡，不显示未经测量的阅读时长，不记录路线进度，也不会自动开启本地阅读记录。

## 内容边界

路线是导航编排，不是新增医学内容、个体化推荐或诊疗路径。标题和关联来自当前频道发布的内容。正式与演示内容不混用，待审校状态仍明确展示；各篇审校状态独立，不因其中一篇通过而宣称整条路线通过。

首页展示当前最多 3 个精选指标入口；其他已发布指标也可从正文进入路线。路线按现有列表顺序展示最多 24 个可访问的关联器官，不声称覆盖全部医学关联。没有关联内容时只保留概念和来源，并解释未展示不代表没有关联。

指标撤回后，路线页返回真实 404，首页入口消失。关联器官撤回后，后续请求不再生成该器官步骤。页面沿用无缓存动态 SSR；已打开的页面不会主动推送刷新，旧链接再次请求时仍受发布权限约束。静态演示使用随项目打包的内容，不代表正式发布渠道。

## 实现与验证

- 共用已有内容 API、发布权限和数据结构，无数据库迁移、无需重新发布内容。
- 路线拥有独立标题与 canonical；演示路线 noindex，正式路线随指标发布入口进入 sitemap。
- 自动检查路由、关系过滤、独立审校状态、首页到器官再到来源的阅读路径、刷新、移动布局、无脚本阅读、内容撤回和加载失败重试。
- `npm run test:topics` 运行路线规则测试；`node scripts/topics-smoke.mjs` 检查浏览器路径；SSR 模式使用 `TEST_SSR=true` 与 `PLAYWRIGHT_BASE_URL`。

本版交付检查：20 项前端规则测试、Vite/Next 构建与 TypeScript 检查通过；静态浏览器的路线、场景入口、阅读、搜索及既有主流程回归通过；隔离测试数据库中的 6 组服务端渲染检查（含真实 HTTP、发布/回滚/撤回）、SSR 路线和既有 SSR 浏览器回归通过。这些自动化结果不代替真实读者研究或医学审校。

这不是“完整主题已通过验收”：分层医学内容、真实专业审校、真实用户理解效果仍待完成。下一轮按路线图推进收藏完善。
