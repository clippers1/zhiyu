# 检索体验（0.0.1-beta.7）

## 读者可获得什么

- 指标目录、收藏筛选和全站搜索使用一致规则，兼容英文大小写、全角字符、空格和连字符。例如 `ＬＤＬ－Ｃ`、`l d l c` 与 `LDL-C`。
- 英文名称、标签、已发布别名及原有正文检索文本都可参与匹配。别名来自编辑维护并发布的快照，本轮没有添加医学同义词字典。
- 标题精确命中最先展示，其次是英文名称/标签精确命中、标题包含、英文名称/标签包含、正文/别名包含；同级保持稳定顺序。结果注明匹配字段类型，不推断哪条内容适用于用户。
- 无结果时，部分英文拼写误差可提示候选词，需用户点击确认；分类造成无结果时可单独清除分类，收藏筛选不会因此扩大到未收藏内容。
- 输入法组合输入期间不提前搜索，输入完成后等待 250ms 再查找。新输入尚未完成或请求未返回时隐藏旧结果，避免点入上一关键词的条目。

## 匹配与候选词边界

格式归一化使用 Unicode NFKC、转小写，再保留拉丁字母、数字和基本汉字。只忽略格式差异，不理解多词逻辑、句子意图或报告数值。纯标点、表情等归一化为空的非空输入返回零结果，空白输入仍表示浏览目录。输入上限 200 字符。

候选词仅在当前范围完全没有匹配时产生，来源为已发布标题、英文名称和标签。只处理两侧长度至少 4 的拉丁字母/数字词，允许一次插入、删除、替换或相邻字符交换；例如 `glcuose` 可以提示已有的 `BLOOD GLUCOSE`。不对短缩写（如 HDL/LDL）、中文近形字、拼音或症状作纠正。结果最多 3 个，不能声称覆盖全部输入错误。

候选词只考察当前筛选范围内按顺序取出的前 200 条摘要，是有边界的辅助功能，不是完整拼写词典。普通匹配和分页不受此 200 条候选范围限制。通用的“试试血糖”等按钮仍只是重新发起查询，不代表该专题一定在当前集合上线。

## 数据与发布一致性

- 线上在 PostgreSQL 内对发布入口的字段做归一化、过滤、排序与分页；摘要来自当前发布快照。总数和当前页由同一条参数化查询产生，用户字符串不拼接进 SQL。
- 离线演示使用同样的归一化、排序和候选规则，保留 JSON 数据访问方式。API 对比测试检查两种适配器在相同快照上的结果、顺序和分页一致。
- 不读取草稿或审校私有字段，不向浏览器返回内部 `searchText`。正式/演示集合、撤回、类型、分类、收藏 ID 和精选条件都在服务端执行。
- 搜索按需读取现有字段，没有持久化新索引、数据库迁移或历史内容重发。发布、回滚和撤回下次查询即生效，候选词也不能保留已撤回内容。
- 新增/修改医学别名仍需要随内容版本发布；正式版本继续受原有医学审校约束。
- 不新增搜索历史或分析埋点。服务器仍会处理正常搜索请求，不能理解成搜索词完全不经过服务器。请勿输入身份信息、联系方式或完整报告。

当前方案会在数据库中计算归一化并进行包含匹配，适合现阶段的小型内容库，不承诺大规模吞吐量。以后内容规模增长，应实测后选择派生搜索索引或专门搜索服务，并保留同等的撤回与权限约束；不为本轮引入额外基础设施。

## 验证

```sh
npm run test:search
PLAYWRIGHT_BASE_URL=http://localhost:5173 node scripts/search-smoke.mjs
```

后台 `npm run test:search` 仅允许独立的 `zhiyu_test` 数据库：验证格式差异、排序、分页、筛选、SQL 参数安全、正式/演示隔离，以及草稿别名不公开、发布/回滚/撤回立即生效。测试使用明确标记的合成别名，不在生产写入测试内容或审校。

浏览器覆盖目录与弹窗搜索、候选确认、清除分类、纯标点、输入法组合输入、旧结果隐藏、移动布局及不存储搜索词。仍需真实读者测试查找习惯、真实输入法及微信内浏览器，不把自动化通过等同于真实使用效果达标。
