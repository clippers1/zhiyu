# 知识内容快速扩展方案

更新：2026-09-20。`0.0.1-beta.19` 已在不增加独立审校前置流程的前提下，把指标专题由 3 个扩展为 9 个，并建立可持续维护的知识扩展流水线。

## 1. 当前机会

产品已经具备搜索、分类、关联器官、专题路线、来源展示、收藏、分享、版本发布和撤回能力，短板不是页面功能，而是只有血糖、血压、血脂三个指标。继续逐篇手改目录和数据库会产生重复劳动，也容易出现正文、目录、来源和线上版本不一致。

本阶段面向普通体检读者，只解释常见项目“测什么、几个子项如何分工、与哪个器官相关、阅读时要注意什么”。不提供数值阈值、疾病判断、用药或治疗建议。

## 2. 三种视角的候选方案

产品视角：按常见体检单形成内容簇；优先覆盖高频搜索；给每篇绑定可靠机构来源；用关联阅读提高连续探索；以读者搜索和反馈决定下一批。

设计视角：统一“基础解释—子项分工—过程关系—阅读提示—来源”的阅读结构；支持中文名、英文缩写和化验单别名搜索；从指标跳到器官；减少首页堆叠；明确不做个人诊断。

工程视角：以单个 JSON 知识包作为可审阅源文件；自动生成目录和搜索摘要；自动校验引用、关系和边界字段；批量同步 CMS 并生成不可变发布版本；发布前检查来源链接可访问性。

## 3. 优先实现的五项

1. **结构化知识包**：一篇内容集中保存正文、搜索别名、关系、来源定位和适用边界，减少多处维护。
2. **目录自动生成**：`npm run content:build` 从知识包生成 `index.json`，`npm run content:check` 阻止目录过期。
3. **严格内容校验**：要求具体来源、段落定位、关键段落引用、适用范围、限制和有效关系；不允许把数值阈值混进基础知识批量发布。
4. **批量发布工具**：显式选择知识标识并确认来源检查后，统一同步数据库、生成演示与正式修订，保留旧修订用于回滚。
5. **首批体检项目簇**：新增血常规、肝功能、肾功能、尿酸、甲状腺功能和尿常规，使指标专题由 3 个增至 9 个。

关键假设：普通读者会按化验单项目名或缩写查找；统一结构能覆盖第一批基础术语；可靠机构页面足以支撑不含阈值和诊疗建议的基础解释。后续用站内搜索未命中词、阅读反馈和真实读者观察验证，不按主观偏好无限铺内容。

## 4. 新增内容流程

1. 从 NLM / MedlinePlus、NIH 专科研究所、WHO 等机构选取直接对应具体知识点的页面。
2. 新建 `public/content/indicator/<id>.json`，填写搜索别名、关键解释、关联器官、来源定位、适用范围和限制。
3. 运行 `npm run content:build`、`npm run test:content` 和前端构建。
4. 人工打开来源并核对页面与中文表达，再运行批量发布命令；工具会再次检查链接可访问性。
5. 验证列表、搜索、详情、来源、器官关联、SSR 和移动端，再部署。

下一批不先定数量。优先观察未命中搜索词，再考虑电解质、凝血、铁代谢、维生素、心电图术语等内容；凡涉及诊断阈值、疾病分级或治疗，不能沿用基础知识快速发布路径。
