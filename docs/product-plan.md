# 知愈产品规划：可靠医学知识的可视化知识馆

更新：2026-09-20。实现基线：`0.0.1-beta.15`。本文按最新定位重写，取代原先以医学编辑、逐篇独立审校和内容平台扩建为主线的规划。

本文是后续决策依据，不表示新功能已实现，也不改变当前生产内容状态或发布权限。执行顺序见 [成果路线图](roadmap.md)，首个专题见 [可视化互动首期方案](visual-learning.md)。

## 1. 愿景与定位

让普通人通过可靠资料、直观图示和动手操作，理解身体如何运作。

知愈是医学基础知识的组织与展示产品，不是在线问诊平台，也不是需要持续原创医学观点的媒体。核心工作是选择成熟知识、组织学习路径、做清楚的中文表达和可交互演示；不要求维护者自建医生团队或高频更新文章。

产品主线：**想了解一个问题 → 看图和操作理解过程 → 阅读必要解释 → 核对来源 → 收藏或分享。**

来源可靠是底座，交互帮助理解是核心价值，后台只是维护工具。动画不能只有装饰作用，每次操作都应帮助读者理解一个具体关系或过程。

## 2. 目标用户与任务

以下为工作假设，尚无真实用户研究证明需求大小。

| 用户任务 | 现有替代方式与困难 | 知愈提供的结果 | 优先级 |
| --- | --- | --- | --- |
| 想知道器官怎么工作、某个过程如何发生 | 搜索长文章、看静态图或视频，难以控制节奏和对应位置 | 点一个结构、走一步过程，能用自己的话解释基本机制 | 第一切入点 |
| 想看懂听到的医学术语或指标名称 | 百科解释专业，容易把概念当成个人诊断 | 把术语连到器官和过程，知道它描述什么、不能说明什么 | 保留现有入口，随主题扩展 |
| 想给家人解释基础知识 | 转发截图容易丢失语境，视频未必方便定位 | 分享能直接打开的专题，保留来源与示意边界 | 复用现有分享能力 |

首期面向一般成年读者的基础解剖与生理认识，不延伸到儿童、孕产妇或复杂疾病的个体化建议。无需用户填写病史、报告或健康数值。

## 3. 成本策略

采用“小主题、深展示、可复用”的方式，而不是“大规模采集、堆文章、扩审批”。

- 主要投入：来源选择与核对、图形与交互制作、中文表达、真实设备测试。
- 控制投入：复用现有 CMS、数据库、SSR、收藏和分享，不重新搭平台，不先建通用动画编辑器。
- 内容维护：稳定基础知识按变化与反馈更新，不承诺每日上新；每次检查记录真实日期。
- 专业协作：仅在涉及争议、复杂解释或高风险内容且确实需要纳入时寻求相应专业核对；没有资源就缩小范围。
- 尚无流量、成本和付费数据，不声称已有低获客成本或可盈利模型；当前不把商业化作为首期验收条件。

## 4. 核心价值与产品形态

### 从“看文章”变成“理解一个过程”

每个互动专题采用相同的外层结构，内部允许不同展示形式：

1. 用一个普通问题说明学什么，例如“血液怎样经过心脏和肺？”
2. 用一幅有标注的示意图建立位置关系。
3. 点击结构查看解释，分步观察过程；提供播放、暂停、上一步和下一步。
4. 图与短文字同步，完整文字和来源仍可独立阅读。
5. 提供可展开的完整文字过程，方便不想操作动画的读者一次读完；不设置答题、评分或学习打卡。
6. 连接现有器官、术语和下一专题，支持收藏、分享和纠错。

首期候选为“心脏与血液循环”，具体范围和验收见 [首期方案](visual-learning.md)。该选题是当前实施建议，不代表已经完成素材授权或脚本核对。

### 展示能力的顺序

**静态结构图 → 点击解释 → 可控制的过程动画 → 主题间关联 → 按需要补视频。**

首期优先 SVG 与现有 React 能力，不默认引入 WebGL、复杂 3D 或新动画引擎。视频用于交互难以表达的内容，不取代可定位的图文；需要字幕、文字稿、来源、授权和移动端流量提示。

### 现有能力的定位

搜索、目录、大字号、收藏、继续阅读、分享和反馈继续保留，服务互动专题的发现与回访。优先接入已有能力，不再以新增按钮、账号或运营看板作为产品进展的主要证明。

## 5. 取舍与内容边界

### 5.1 轻量内容流程

选一个问题 → 找到合适来源 → 核对使用方式 → 列知识点与出处 → 编写图文/动画脚本 → 检查是否忠实表达 → 发布版本 → 按反馈维护。

这可以由同一位维护者完成，不要求普通基础知识逐篇经过独立医生审批。“编辑核对”只表示检查来源、表达和素材，不等于专业医学审校。

| 内容风险 | 处理方式 |
| --- | --- |
| 成熟、稳定的基础解剖、生理和术语 | 维护者核对具体来源、图示与文字一致性、许可和简化边界后，走拟建设的来源整理发布路径 |
| 疾病机制、争议、指南差异、数值标准、特殊人群等易被误用内容 | 优先不纳入首期；确需纳入时记录适用范围并进行针对性专业核对，疑点未解决不发布相关结论 |
| 个人诊断、治疗选择、用药剂量、报告打分 | 不在当前产品范围，不因增加审校流程就自动纳入 |

保留的底线：

- 每个关键知识点能定位到具体来源页面、章节或图表，不能只列机构首页。
- 记录来源标题、机构、URL、原文版本/日期（未知则如实标注）、本次核对日期和具体使用权限。
- 页面公开可读不等于图片、视频、全文和译文可转载；优先自行组织文字、原创图示或使用明确授权素材。
- 自绘图和动画同样要核对事实：方向、顺序、标签不能错误；非真实比例、时间和速度须明确为示意。免责声明不能替代准确性检查。
- 有冲突、无法找到依据或无法确认素材权限时，删减该表达或换素材，不凭印象补全。
- “参考某机构资料”不等于“该机构背书”；未经专业审校不能显示为“医生审核”。

来源候选继续沿用公共卫生机构、权威医学教育资料和现有来源库，先按主题人工选取具体材料，不接全量抓取服务。旧 [知识平台方案](knowledge-platform.md) 的逐篇强制审校设想不再作为产品前置条件。

### 5.2 发布规则需要后续改造，不靠修改文案绕过

正式 API 已支持版本绑定的“依据来源整理”发布，演示频道仍为 `pending` 且 noindex。基础知识发布不要求独立专业审校；现有 8 篇内容也不会因规则存在而自动认定为已核对。

计划把“允许公开发布”“来源核对情况”“专业审校情况”分开建模：

- 基础知识满足来源与表达检查，可由授权维护者显式发布，显示“依据来源整理”，不产生虚假审校记录。
- 真实专业审校作为可选、版本绑定的信息保留；不能将编辑核对转换成 `reviewed`。
- 保留草稿隔离、不可变快照、审计、回滚、撤回、权限及反馈机制。
- 旧内容逐篇决定是否满足新路径，不批量改状态；页面、API、分享卡片、搜索收录同步迁移并测试。

详见 [路线图 P0](roadmap.md)。这属于必要的规则减负，不是继续扩建审批系统。

### 5.3 暂缓范围

读者账号、云同步、社区、签到、个人健康档案、报告上传/OCR、AI 个体化解读、在线问诊、电商、App/小程序、通用 3D 引擎、全站视频化和大规模采集均暂缓。源码许可证与引用素材授权分别处理，不在规划中擅自选择许可证。

## 6. 怎样判断有价值

目标北极星信号是“读者完成一个学习任务，并能正确解释其关键关系”。目前只能通过自愿参与的小样本任务观察确认，不能用停留时间、动画播放次数或现有反馈条数冒充理解人数。

首个迭代只关注一件事：**心脏专题是否帮助读者讲清预设的基础循环路径，且没有产生危险误解。**

| 信号 | 获取方式 | 使用边界 |
| --- | --- | --- |
| 理解任务完成情况 | 事先依据来源写好答案要点，再观察读者复述 | 小样本用于找问题，不证明全体读者效果 |
| 操作任务完成情况 | 是否能无提示找到结构、控制过程、查看来源 | 不把点击数当学习效果 |
| 主动保存/分享的意愿与原因 | 任务后询问，结合现有反馈 | 意愿不等于真实留存或传播 |
| 单主题制作与维护成本 | 记录脚本、图形、实现、核对各环节实际投入 | 用首个样板建立基线，不预编工期 |

不默认增加行为追踪或记录健康兴趣。未来如需统计，先另行确定匿名化、同意、保留期和隐私说明。

## 7. 增长方式

走产品体验驱动：具体问题入口 → 有帮助的互动解释 → 自愿收藏/分享 → 新读者打开对应专题。来源合格且按新规则发布的页面才逐项评估搜索收录；不因改定位直接取消现有演示 noindex。

优先网站和现有干净链接/分享卡片，验证手机及微信真实体验后再考虑渠道增强。不以病症恐吓、疗效承诺、虚构“热门”或强迫注册吸引访问。

## 8. 能力与协作

- 自建：知识组织、中文解释、互动脚本、原创示意图、可访问的移动端体验。
- 复用：React、Next.js、Payload、PostgreSQL，以及现有阅读、发布和维护模块。
- 外部获取：适当许可的参考材料与素材；必要时针对明确问题进行专业协作，不要求常驻编辑部。
- 必须人工完成：来源适用性和许可判断、图文表达核对、真实用户观察；自动测试验证程序与约束，不证明医学正确性。

## 9. 差异化与待验证假设

公开医学知识本身不是独占壁垒，单个动画也容易复制。可能积累的优势是清楚的中文解释、跨主题一致的交互、经过验证的教学脚本以及可维护的出处映射，目前尚不能声称已经形成壁垒。

| 假设 | 最便宜的验证 | 不成立时怎么调整 |
| --- | --- | --- |
| 用户需要动手控制过程，而不仅是看视频 | 同一主题的图文与交互版本做小样本任务比较，交替呈现顺序 | 保留有效图文，删掉无帮助的操作 |
| 心脏循环适合作为样板 | 先用分步静态图讲一遍，再询问困惑点 | 调整脚本/范围，不先投入精细动画 |
| 一个模板可以支持多个主题 | 第二个主题尝试复用结构、步骤与来源组件 | 根据真实差异抽象，不提前建编辑器 |
| 小团队可以持续维护 | 记录首个主题的实际制作与维护成本 | 缩小每批范围，不追求文章数量 |

策略一致性：成熟基础知识控制内容成本与风险，互动解释创造价值，小主题验证控制工程投入，复用现有阅读能力承接回访。后续优先级按验证结果调整，不再以审校记录数量或后台模块数量衡量产品成熟度。
